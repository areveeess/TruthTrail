<interfaces>
Provider facts (RESEARCH F-13, public pages read 2026-10-18; the container never calls the API): Free plan = 100 requests per day, up to 10 articles per request, 12-hour delay, 1 request per second, non-commercial, daily reset at 00:00 UTC; a 403 means the daily quota is reached and is account-wide; a 429 is the per-second limit; terms allow reasonable caching of API responses and forbid redistributing access to the API and building a database to avoid the usage limits, so store headline, URL, source name and times only, offer no bulk export route and attribute GNews. A topic phrase is at most 200 characters.

Existing adapter facts (read src/truthtrail/services/gnews.py): `fetch_news(query, api_key)` sends params q, lang en and max 1, key only in the X-Api-Key header, no redirects, up to 3 attempts with backoffs 0.3 and 0.6 s inside an 8 s budget, retries only timeouts, connect errors that are not TLS errors and statuses 500, 502, 503 and 504; `_classify_status` maps 401 to 502 upstream_unauthorized, 403 to 502 upstream_forbidden, 429 to 503 upstream_rate_limited with Retry-After, other unexpected statuses to 502 upstream_bad_response; the article model validates title, source.name and publishedAt and ignores other keys; the function returns dicts with title, source and publishedAt (UTC ending in Z). Tests of the adapter assert the exact parameter set and max 1 by default, so those defaults must not change.

Job algorithm (D-26): take the news advisory lock; load and validate the topics file; upsert news_queries by slug; due topics are those never refreshed or last refreshed more than NEWS_MIN_REFRESH_HOURS ago, never-refreshed first, then oldest first; for each due topic up to NEWS_MAX_CALLS_PER_RUN: in its own committed transaction count news_fetches rows with called_at later than now minus 24 hours, stop the run when the count has reached NEWS_DAILY_BUDGET, otherwise insert a pending row and COMMIT; wait at least 1.1 s since the previous call; call the adapter; then in one transaction store the headlines (claims upsert by claim_key; a headline already stored is left as is), set the fetch outcome (ok, empty, or the error code truncated to 24 characters) and update news_queries last_attempt_at, last_success_at (only on success, including an empty answer) and last_status. Stop and exit rules as in the truths. The claim for a headline: kind news_headline, text the headline, text_hash and claim_key as lowercase base32 truncated SHA-256 digests (26 characters) of the kind and the canonical URL (or the headline when the URL is missing), url_canonical from `truthtrail.ingest.selection.canonicalise_url` (http and https only; NULL otherwise), link_domain its host, source_name, published_at, lang en, query_id the topic's id; no article body is requested or stored.

Topics file shape: a TOML array of tables, each with a slug (lowercase letters, digits and hyphens, 1 to 64 characters, unique) and a query phrase; a comment at the top says topics are subjects or events, never named individuals (the prototype's hardcoded celebrity names were a defect), and that the owner reviews the list in the plan summary.

/v1/news shape: query parameters topic (slug pattern) and limit (1 to 10, default 10 per topic); the response has meta (V1Meta), a provider notice string naming GNews and its up-to-12-hour delay on the free plan, and topics, each with slug, query, data_as_of (that topic's last success), last_status and headlines (headline, url, source_name, published_at). Headline text is publisher text, rendered by clients as plain text.
