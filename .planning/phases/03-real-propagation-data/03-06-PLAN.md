<interfaces>
Resolver contract (RESEARCH Pattern 7, prototype executed there; D-14, D-22). Input rows: uri (the keyed key), edge_kind (root, reply, quote, repost), parent_uri or None, observed_at (aware), account (a string or None), deleted (bool). Output: per uri a state in none, resolved, orphan, invalid; the resolved parent uri or None; depth (None for reposts, orphans, disconnected and invalid nodes; 0 for the root); a disconnected flag; the canonical order list; and the rollup. Rules that make it order-independent: iterate over sorted uris; rows with the same uri collapse to the smallest tuple (conflicting duplicates are resolved by value, never by arrival); reposts are never attachable parents and a child whose parent row is a repost is invalid; a self-parent and every member of a cycle are invalid regardless of the node the walk starts from; a child of a present-but-orphan parent is resolved but disconnected; connectedness and depth come from a walk from the root over resolved reply and quote edges; a repost whose subject is connected is connected (a fan-out leaf) and one whose subject is missing is orphan; the order is order_events over CascadeEvent values (event_id is the uri key so ties break on it) with invalid and cycle members given no parent so order_events never raises; order violations are counted with find_order_violations, never raised and never repaired by editing a timestamp (D-08). Factor three behaviours into private module-level functions so the mutation tests can replace them: the duplicate chooser, the iteration order and the cycle-member finder.

Rollup definitions: event_count, reply_count, quote_count, repost_count and unique_accounts count NON-deleted rows (unique_accounts over non-null accounts); orphan_count and disconnected_count count non-deleted orphan or disconnected rows (disconnected_count includes orphans and all their descendants and invalid nodes); deleted_count counts tombstones; max_depth is the maximum depth over connected non-repost rows INCLUDING tombstones because the skeleton stays connected, 0 when only the root; order_violation_count covers all rows; events_1h counts non-deleted rows with observed_at in the half-open window (as_of minus one hour, as_of]; first_event_at is the earliest observed_at and last_event_at the latest observed_at of non-deleted rows (all rows when every row is deleted). An invalid count is returned in the result and logged but has no cascades column (D-20): the tree endpoint shows parent_state per node.

Write-back: for each dirty cascade (enrich_dirty true or rollup_version different from the current constant, ordered by id, at most --max-cascades per run) open one transaction, `SELECT ... FROM cascades WHERE id = :id FOR UPDATE SKIP LOCKED` (skipping a locked cascade leaves it dirty; the collector's own UPDATE that marks a cascade dirty waits for this lock, so a flag can never be lost), load its events (at most TRACK_MAX_EVENTS_PER_CASCADE rows by construction), resolve, UPDATE only the events whose parent_event_id, parent_state or depth changed, UPDATE the cascade counters, enrich_dirty false, rolled_up_at = as_of and rollup_version. as_of defaults to the stream time of the latest committed ingest checkpoint (data_as_of), overridable with --as-of; with no checkpoint there is nothing to enrich. Any unexpected exception for one cascade is counted by class name, leaves that cascade dirty and does not stop the run.

Purge parameters (all from Policy, all with an explicit as_of; D-16, D-18): RETENTION_TEXT_DAYS (root text), RETENTION_CASCADE_DAYS (whole cascades), RETENTION_TOMBSTONE_DAYS (tombstone rows, every edge kind including roots, after deleted_at), RETENTION_NEWS_DAYS (news_headline claims and news_fetches rows), RETENTION_DORMANT_DAYS (0 disables; a positive value removes cascades whose only event is the root after that many days). Deleting a cascade deletes its events through the foreign key; after tombstone deletion the touched cascades are marked dirty so enrich turns the children into orphans; claims referenced by no cascade or event and of kind social_link are removed; accounts with no events are removed; ingest_runs older than RETENTION_CASCADE_DAYS are removed (counts only, no personal data). Deletes run in bounded batches (a LIMIT per statement, looped until none are left or --max-seconds is reached).
