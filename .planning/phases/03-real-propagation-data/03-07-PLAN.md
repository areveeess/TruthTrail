Contract details (D-23, D-24, D-25):
- V1Meta: synthetic Literal[False]; data_as_of AwareDatetime or None; source_status Literal ok, empty, stale; source_mode Literal live, replay; observed_since AwareDatetime or None. Status rule: no committed checkpoint means empty with data_as_of null; otherwise stale when now minus data_as_of exceeds INGEST_STALE_AFTER_SECONDS, else ok; an empty filtered result with data present is ok. source_mode is replay when the latest ingest run was a replay, else live. `now` comes from an injectable app clock (create_app gains a `clock` keyword defaulting to the UTC wall clock) so tests control staleness.
- Cursor: base64url of a JSON array [sort, value, id] where sort is recent or velocity, value is last_event_at in integer microseconds or events_1h, id the cascade id; decoded and type-checked by an AfterValidator that raises ValueError so it renders as the existing 422 problem+json with loc ["query","cursor"]; a cursor whose sort differs from the requested sort is a 422; the timestamp bound is rebuilt EXACTLY from integer microseconds in Python (no float), and the keyset predicate compares the row tuple (last_event_at, id) or (events_1h, id) against it with bound parameters; order is descending on both columns; the query fetches limit plus one to know whether a next page exists.
- Tree: load the cascade's events with their pseudonym (join to accounts), build CascadeEvent values with the resolved parent_event_id, take order_events, apply the optional kinds filter (values reply, quote, repost; the root is always kept; dropping a kind that has children detaches their subtrees, which are then returned as detached roots; dropping reposts is closure-safe), cap at the policy maximum, compute edges only between shown nodes, and return roots as the root plus every shown node without a shown parent. Account value is the first 8 characters of the pseudonym or null for a tombstone.
- Timeline: ladder of bucket sizes 60, 300, 900, 3600, 21600 and 86400 seconds, smallest one with at most the policy maximum number of buckets for the span between the first and last non-deleted event, else the span divided by (maximum minus one) rounded up; SQL `date_bin(:stride, observed_at, :origin)` with the stride bound as an interval parameter and the origin the cascade's first_event_at; zero-count buckets are filled in Python so the series is dense; counts exclude tombstones. date_trunc and extract are never used (the AST rule of plan 03-03 enforces it).
- Stats: cascades_total, cascades_with_deleted_root, events_by_kind (root equals the number of cascades; reply, quote, repost from the rollup sums), events_total, orphans_total, disconnected_total, deleted_total, observed_since (earliest first_event_at), ingest_lag_seconds (now minus data_as_of or null), ingest_gaps_total, last_run (status, mode, started_at, finished_at or null), all from cascades and ingest_runs only.
- Gap counting per cascade: fetch the gap spans of ingest_runs once (a small table) and count the overlaps with the cascade's [first_event_at, last_event_at] in Python, with integer microseconds.
- Errors: OperationalError whose original exception carries SQLSTATE 57014 or 55P03 gives code database_timeout, any other OperationalError and `sqlalchemy.exc.TimeoutError` (pool exhaustion, which is NOT a DBAPIError) give database_unavailable; both are 503 with a Retry-After header of 5 seconds, `problem_body(503, ..., source_status="database_unavailable" or "database_timeout", upstream="database")`; only `type(exc).__name__` is logged; every other database error propagates to the catch-all middleware (generic 500). The /v1 OpenAPI declaration is {422, 429, 500, 503} built from `_problem_declaration` with a 503 description about the database; 404 for an unknown cascade id comes from the generic router handler (problem+json, code http_error) and is intentionally not declared, exactly like an unknown path.
- Policy at construction: `create_app` stores `app.state.policy = get_policy()` before building routers (Policy has no required fields; an invalid value raises ConfigurationError naming the variable, the same pattern as BootSettings); registrars read `get_policy()` when they define Query bounds.
- Description wording (copy guard): captions say 'Observed subset of public Bluesky posts, as of the stated time' and descriptions use 'flag for human review'; never wording that claims to determine truth.
