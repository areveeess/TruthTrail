<interfaces>
Current adapter (src/truthtrail/services/gnews.py): `fetch_news(query: str, api_key: str) -> list[dict[str, str]]`; one `requests.get(GNEWS_URL, params={"q": query, "lang": "en", "max": 1}, headers={"X-Api-Key": api_key}, timeout=TIMEOUT, allow_redirects=False)`; exception order `Timeout`, then `ConnectionError`, then `RequestException`; status mapping 401 and 403 to 502, 429 to 503 with Retry-After from `_retry_after`, any other non-200 to 502 `upstream_bad_response`; `_fail(status, code, detail, retry_after=..., upstream_status=...)` logs `gnews request failed: code=%s upstream_status=%s` at WARNING and raises `UpstreamError(...) from None`. `DEFAULT_RETRY_AFTER = 30`, `MAX_RETRY_AFTER = 3600`.
Target constants and seams (names are fixed because tests patch them): `BACKOFFS = (0.3, 0.6)`, `MAX_ATTEMPTS = 3`, `BUDGET = 8.0`, `CONNECT_TIMEOUT = 3.05`, `READ_TIMEOUT = 10.0`, `RETRY_STATUSES = frozenset({500, 502, 503, 504})`; module-level functions `_monotonic() -> float`, `_sleep(seconds: float) -> None`, `_jitter(low: float, high: float) -> float` that wrap `time.monotonic`, `time.sleep` and `random.uniform` (the last needs `# noqa: S311` with the reason "backoff jitter, not security"). `fetch_news` must call them through the module globals at call time so monkeypatching works.
Loop semantics: record `start = _monotonic()`; for attempt 1 to 3: `remaining = BUDGET - (_monotonic() - start)`; stop if `remaining <= 0`; request with `timeout=(min(CONNECT_TIMEOUT, remaining), min(READ_TIMEOUT, remaining))`. A failure is retryable when it is `requests.exceptions.Timeout`, a `ConnectionError` that is not an `SSLError`, or a response status in RETRY_STATUSES. `SSLError` keeps its Phase 1 mapping (503 upstream_unreachable) without a retry; any other `RequestException` keeps 502 upstream_bad_response without a retry; everything else is classified exactly as today. If the failure is retryable and attempts remain, compute `delay = BACKOFFS[attempt - 1] + _jitter(0.0, 0.1)`; if `(_monotonic() - start) + delay >= BUDGET` give up, otherwise log one INFO line (attempt number, code, upstream status; never URL, key or exception text) and `_sleep(delay)`. Giving up or exhausting attempts calls `_fail` with the Phase 1 mapping of the LAST failure. Keep `except Timeout` before `except ConnectionError` (a ConnectTimeout is both).
Known limitation to document in a code comment: `requests` read timeouts apply per socket read, so a server that drips bytes can exceed the budget; GNews bodies are tiny (`max=1`), so this is accepted.
</interfaces>
