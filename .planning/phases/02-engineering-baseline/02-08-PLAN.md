Handler flow after this plan (within the already rate-limited function): look up; on a hit set `response.headers["X-Cache"] = "hit"` and return the stored object; on a miss compute the result exactly as today (demo fixture or live fetch), store it, set `X-Cache: miss`, return it. Exceptions propagate before the store, so errors are never cached. The fetch happens OUTSIDE the cache lock (it blocks on the network); two simultaneous misses may both fetch, which the rate limit bounds.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| request query -> cache key | Attacker-chosen strings become keys |
| threadpool workers -> shared cache | Concurrent access to a non-thread-safe structure |
| cache -> client | Stored data is replayed to later callers |
